# Agent notes for Touchline

One page of football a day, produced by a three-part machine with one hard
boundary: **Python produces facts, the brain produces prose, the site
produces pixels.** Work on one side of a boundary without leaking into
another.

Touchline runs its own palette (pitch green, club blue) on purpose, but
follows the shared **structure** — see `../design-system/` for the token
contract and the cross-app product/interaction invariants.

## Map

- `src/touchline/` — facts CLI (`uv run touchline facts`). Pure core
  (`core/facts.py` — no I/O, injected `now`), source clients behind
  protocols (`sources/espn.py` default, `api_football.py`,
  `football_data.py`), config loader. Owner preferences live in
  `touchline.config.json` (club, competitions, timezone, source, feeds,
  voice) — never hardcode a club, competition, or timezone.
- `brain/` — the daily editor. `curate.sh` runs headless Claude with
  `prompt.md` + the facts bundle; `validate.mjs` is the **schema
  authority** for digest entries. If you change the schema, change the
  validator, the prompt, and the site renderer in the same branch — they
  are four seams of one contract (facts bundle → prompt → validator →
  renderer), and drift between them is the #1 recurring bug class here.
  The FPL planner is a second product with the same four seams:
  `uv run touchline fpl` → `fpl-prompt.md` (via `curate-fpl.sh`) →
  `validate-fpl.mjs` → `site/app.js` (the root page).
- `functions/` — Cloudflare Pages Functions, a sibling of `site/` (NOT inside
  it). Today that is one route: `api/live.js`, a same-origin, read-only,
  whitelisted proxy of the FPL API. It exists because that API sends no CORS
  headers, so the browser cannot call it directly; it also joins picks +
  league + fixtures server-side so the page makes one request. Every sub-fetch
  degrades independently — a dead league drops that section, never the
  response. `deploy.sh` asserts the Functions bundle uploaded, because the
  silent failure mode is /api/* 404ing to the static site.
- `site/` — static reader. No framework, no build step, no CDNs. All
  data-derived strings go through `esc()`. `site/data/digests.json` is the
  database: **append-only**, one entry per date; past entries are never
  edited (schema migrations by explicit owner decision only).
  `site/data/fpl.json` (the FPL planner at `/`) deliberately
  diverges: it's a **living document** — current-state sections are
  replaced wholesale each run; only its `log[]` is append-and-settle
  (open verdicts get settled, settled entries are frozen).
  `site/data/config.json` is generated by `deploy.sh` — never hand-edit.

  **Site map (since 2026-08-22):** `/` is the FPL planner (the front door),
  `/digest/` is the daily football page, `/about/` is about. `/fpl/*` 301s to
  `/` via `site/_redirects`. All three pages share `style.css` — the FPL
  component block is appended at the end, and anything it would redefine was
  deliberately dropped so the digest keeps the base rules.

## Commands

```sh
uv run pytest -q              # Python suite — keep green
uv run ruff check .           # lint (line-length 100)
node brain/validate.mjs       # digest DB must always validate
node brain/validate-fpl.mjs   # fpl.json must always validate
node --check site/app.js site/digest/app.js functions/api/live.js  # after JS changes
./brain/curate.sh --no-deploy # full daily digest run without publishing
./brain/curate-fpl.sh --no-deploy  # full FPL run without publishing
./deploy.sh                   # copy config + wrangler pages deploy
cd site && python3 -m http.server  # local preview
```

## Rules that have bitten before

- The brain must never invent facts (scores, fees, stats) — prose comes
  from fetched sources; structured club data is copied verbatim from the
  bundle. `club_form` scores are club-digit-first; `latest_result.score`
  is home–away ordered — the swap rule lives in `prompt.md`, don't weaken it.
- Competition labels on stat boards are short codes ("PL", "CL", "FR");
  only the table heading uses the human league name.
- ESPN is unofficial: keep the wide date window (120d back / 45d forward)
  and `limit=400` — silent truncation drops future fixtures mid-season.
- Design changes are **mockup-first**: iterate
  `docs/superpowers/mockups/2026-07-25-site-mockup.html` with the owner
  before touching `site/`.
- Specs and plans live in `docs/superpowers/`; read the latest before
  structural changes.

## Deployment

Cloudflare Pages project `touchline-pl`, live at https://touchline-pl.pages.dev
(no custom domain). Renamed from `touchline-chelsea` on 2026-08-22 when the
site stopped being Chelsea-only; the old project is left untouched, not
redeployed. Deploys are
non-interactive
(`CI=1`) — just `./deploy.sh`. The digest runs
itself: `brain/auto.sh` fires hourly via launchd (`com.kb.touchline.plist`,
same pattern as antifeed — pull with autostash + timeout, then two
independent freshness checks: today's digest exists → skip `curate.sh`,
fpl.json's `generated_at` is today → skip `curate-fpl.sh`; a failure in
one never starves the other). Manual runs still work any time.
