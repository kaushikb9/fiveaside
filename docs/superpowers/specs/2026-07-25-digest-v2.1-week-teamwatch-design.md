# Digest v2.1 — week briefing, team watch, wider data windows

**Date:** 2026-07-25
**Status:** Approved (mockup iteration signed off in conversation).
Mockup authority: `docs/superpowers/mockups/2026-07-25-site-mockup.html` (updated today).

## What changes and why

Owner feedback on the first live digests: prose sections were single-paragraph
dumps; "Yesterday" is too narrow a window; no player-level content; the shipped
app showed no upcoming fixtures or form in pre-season. Root causes for the last
two: the facts layer's 14-day upcoming horizon (next PL match is ~27 days out in
July) and ESPN's 45-day past window (last season ended 62 days ago). Inspiration
references: The Athletic (kicker-led briefings), SBNation club blogs,
FotMob, OneFootball.

## 1. Digest schema (brain/validate.mjs is the authority)

- **`week` replaces `yesterday`** — REQUIRED non-empty array of
  `{kicker, text}` (both non-empty strings). The last ~7 days: results,
  transfers, friendlies, club news. A `yesterday` key is REJECTED with a
  migration message (same pattern as the earlier `club.results` rejection).
- **`team_watch`** — OPTIONAL array of `{name, tag, note}` (non-empty
  strings) plus optional `talent` (boolean). Stars and academy prospects;
  `tag` reads "RW · 19" or "Academy · 17".
- Everything else (headline, today, club block, wider, read, rivals, source,
  image) unchanged.
- **Migration:** the existing 2026-07-25 entry is mechanically migrated in the
  same commit that changes the validator (its `yesterday` prose becomes a
  single `week` item). One-time exception to append-only, done by the owner's
  request, not by the brain.

## 2. Section order (site renderer)

This week → Today → Team watch → One good read → Rival watch →
The wider game → Archive.

## 3. Site (implement the updated mockup)

- CSS: the updated mockup's stylesheet verbatim (line-height 1.65, section
  `h2` hairline rules, `ul.brief` kicker list, `.players`/`.avatar`
  team-watch styles, 660px column) plus the existing data-driven extras
  (`.empty`, `.thumb.ph`).
- `week` renders as the `ul.brief` list (`<strong>` kicker + dimmed tail).
- `team_watch` renders as player rows: initials avatar (first letters of up
  to two name words), name, tag chip, note; `talent: true` gets the
  green-tinted avatar and tag.
- Old `yesterday` field no longer rendered anywhere.

## 4. Brain prompt

- Schema block matches the new validator exactly.
- `week`: 3–5 items; kicker ≤ 6 punchy words ending with a period; text 1–2
  sentences; drawn from the last 7 days of facts + discourse; pre-season weeks
  lean on transfers and friendlies.
- `team_watch`: 2–4 players — in-form stars, fitness watches, academy talent
  (set `talent: true`); notes come only from fetched sources, never invented
  stats.
- `yesterday` is gone; never emit it.

## 5. Data windows (the pre-season fix)

- `sources/espn.py`: `PAST_DAYS` 45 → **120** (tail of last season fills the
  form strip in pre-season), `FUTURE_DAYS` 21 → **45** (next season's opening
  fixtures visible from mid-July). League map gains
  **`FRIENDLIES → club.friendly`** (verified live: 50 events/2 weeks,
  Chelsea v Juventus present).
- `core/facts.py`:
  - `club_upcoming` = the next **5** SCHEDULED club fixtures sorted by
    kickoff, **no date ceiling** (drop `UPCOMING_HORIZON_DAYS`, add
    `UPCOMING_LIMIT = 5`).
  - Noise cap for global feeds like friendlies: in `yesterday_results` and
    `today_matches`, always keep club-involved rows but cap non-club rows at
    **10** per list (earliest kickoffs win; relative order preserved).
- `touchline.config.json`: competitions become `["PL", "CL", "FRIENDLIES"]`.
  football-data and api-football have no FRIENDLIES mapping — under those
  sources that competition degrades gracefully per the existing
  unknown-competition path (documented in the config comment in README).

## Not building

Player photos (no reliable keyless source; initials avatars); a separate
friendlies page; automatic season rollover for api-football's season param
beyond the existing month-based rule.
