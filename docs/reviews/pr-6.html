The flow

This change adds two thin layers — a renderer and a CLI — on top of work that already existed (the source client and the digest builder). Data moves left → right; nothing flows back.

The new code in cli.py is just the wiring. run_digest() is the testable core of the CLI — it takes a MatchSource and returns a string, so a test can hand it a fake and never touch the network. main() is the only place that constructs the real client and reaches for stdout.

# cli.py — the whole orchestration, ~12 lines
def run_digest(source: MatchSource, *, now: datetime | None = None) -> str:
    if now is None:
        now = datetime.now(UTC)
    res    = source.fetch_matches("WC")
    digest = build_digest(res.fixtures, res.results, now=now)
    output = render_markdown(digest)
    if not res.ok:
        output += f"\n> ⚠️ Some data was unavailable: {res.error}"
    return output

Concepts that may be new

Five ideas here are worth pausing on — each is a deliberate architectural choice, not incidental.

1 · Ports & adapters (the MatchSource seam)

run_digest doesn't ask for a FootballDataClient. It asks for a MatchSource — an interface (a "port"). The real HTTP client is one adapter; the test's _FakeSource is another. Same shape, different guts.

# the test never opens a socket — it just satisfies the port
class _FakeSource:
    def fetch_matches(self, competition: str) -> SourceResult:
        return self._result   # a hand-built result
Why right here: the digest logic is the valuable part and you want to test it offline, fast, deterministically. The port lets the network live at the very edge (main()) while everything inside stays swappable.

2 · Protocol typing — structural, not inherited

In sources/base.py, MatchSource is a typing.Protocol. Notice the fake source does not subclass anything. Python's Protocol means "if it has a fetch_matches(competition) → SourceResult method, it counts" — duck typing the type checker can verify. This is the same idea as a Go interface.

@runtime_checkable
class MatchSource(Protocol):
    def fetch_matches(self, competition: str) -> SourceResult: ...
Why right here: the fake in the test stays a plain class with zero import coupling to the source package — yet mypy/ruff still confirm it fits the port. Less ceremony than abstract base classes.

3 · Graceful degradation via a result object

A fetch can fail (network down, bad token). Instead of throwing, the source returns a SourceResult carrying ok=False, empty lists, and an error string. The CLI builds the digest from whatever came back and appends a note rather than crashing:

if not res.ok:
    output += f"\n> ⚠️ Some data was unavailable: {res.error}"
A failed run still prints a valid digest header plus a blockquote: > ⚠️ Some data was unavailable: boom. The user sees something useful, never a stack trace.
Why right here: this is a daily glanceable tool. "Show me what you have, flag what's missing" beats "explode on a flaky API". The error is data, not an exception.

4 · Pure core vs. impure shell

render_markdown and build_digest are pure: same inputs → same output, no clock, no I/O, no network. Two clues prove it: the renderer imports only from core.digest, and time enters only through the injected now parameter — datetime.now(UTC) is called in exactly one place, defaulted in run_digest.

# tests pin "now" so the date string is deterministic
NOW = datetime(2026, 6, 14, 12, 0, tzinfo=UTC)
out = run_digest(_ok_source(), now=NOW)
assert "# Touchline" in out
Why right here: injecting the clock makes "Sunday, 14 June 2026" testable without freezing system time. Purity is what makes the core trivially unit-testable.

5 · The console-script entry point

Three lines in pyproject.toml turn a function into a terminal command:

[project.scripts]
terrace = "terrace.cli:main"

On install, the packaging tool generates a terrace executable that calls terrace.cli.main(). main() returns an int exit code (0 success, 2 for no/unknown subcommand) — the Unix convention — and the if __name__ == "__main__" guard does raise SystemExit(main()) so python -m terrace.cli works too.

Why right here: it's the cheapest possible "surface". The README's promise — uv run terrace digest — is now wired end to end with zero new dependencies.

Decisions & trade-offs

✓ Chosen now

  • One subcommand, no flags — smallest useful slice.
  • Markdown output (renders anywhere, diff-friendly, terminal-readable).
  • argparse from stdlib — no Click/Typer dependency.
  • Zero-padded day (%d) for cross-platform portability (%-d is not portable).
  • Failure path appends a note; never raises to the user.

· Deferred (on purpose)

  • HTML rendering / the FastAPI PWA surface.
  • --date, --competition, --json flags.
  • Colored output, multiple subcommands.
  • RSS / news, any new dependency.

The renderer signature (DailyDigest → str) leaves room for an html.py sibling later without changing the CLI's wiring — the digest stays surface-agnostic.
