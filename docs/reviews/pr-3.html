Digest core — turn fixtures & results into a DailyDigest

Given a list of matches, build a structured daily digest — yesterday's results each with a one-line story, today's kickoffs in IST, and one "match of the day" — as pure, fully-tested functions. No I/O, no clock, no network.

Concepts that may be new

1 · A pure core, enforced by a test — the architectural spine

digest.py imports only terrace.core.models + stdlib. No httpx, no fastapi, no os, no filesystem. "Pure" means the same inputs always give the same output, with no side effects — which is exactly what makes this code trivial to test and reason about.

What's notable is that purity isn't just a comment — it's asserted. The module literally reads its own source and checks for banned strings:

# tests/test_digest.py
def test_digest_module_has_no_forbidden_imports():
    source = Path("src/terrace/core/digest.py").read_text()
    for forbidden in ("terrace.sources", "httpx", "fastapi", "import os", "from os"):
        assert forbidden not in source

Why it's the right call: dependency direction points inward (sources depend on core, never the reverse). A future refactor that "just imports the client to grab data" would turn the test red instead of quietly coupling the core to the network.

2 · Time is an argument, never datetime.now() — deterministic time

The signature is build_digest(fixtures, results, *, now: datetime). The function never calls the clock itself; the caller supplies the moment. That single decision is why every test can pin "today" to 2026-06-13 and get a stable result — no mocking, no frozen-clock library, no flaky midnight failures.

The * forces now to be passed by keyword (now=...), so call sites read clearly and you can't accidentally pass it positionally.

3 · Frozen pydantic models as immutable value objects

All four outputs use class X(BaseModel, frozen=True). Frozen = once built, fields can't be reassigned (assigning raises). They behave like immutable records: validated on construction, comparable by value, safe to pass around without anyone mutating them behind your back.

class MatchCard(BaseModel, frozen=True):
    fixture: Fixture
    kickoff_ist: datetime   # tz-aware, already in IST
    kickoff_label: str      # "8:30 PM IST"

Note match_of_the_day: MatchOfTheDay | None — the "no matches today" case is modelled in the type itself, so callers are forced to handle it.

4 · Fixed UTC offset for IST, deliberately not zoneinfo

India Standard Time is UTC+5:30 with no daylight saving, ever. So a fixed offset is not an approximation — it's exact:

IST = timezone(timedelta(hours=5, minutes=30))

Using zoneinfo would pull timezone data off the filesystem (a tz-database lookup) — an I/O side effect that would violate the pure-core rule for zero benefit here. to_ist also treats a naive datetime as UTC, so the function is total: it never throws on missing tzinfo.

The label formatter rolls its own 12-hour clock (hour % 12 or 12) instead of strftime("%-I"), because the %-I "no leading zero" flag is platform-specific (breaks on Windows). Small portability hedge, verified by test_format_ist_morning_no_leading_zero.

5 · A heuristic expressed as a sort key

"Match of the day" is whichever kickoff sits closest to 8 PM IST. Rather than branching, it's a single min() over a tuple key — Python compares tuples left-to-right, which gives you the tie-break ladder for free:

best = min(cards, key=lambda c: (
    abs(c.kickoff_ist.hour - 20),  # 1. nearest to 8 PM
    c.kickoff_ist,                  # 2. else earliest
    c.fixture.id,                   # 3. else stable by id
))

The third element makes the pick fully deterministic even when two matches are equidistant and simultaneous — no "it depends on list order" ambiguity. pick_match_of_the_day([]) returns None rather than raising.

Decisions & trade-offs

Chosen Structured data only — DailyDigest is plain objects, no strings-for-display beyond the story/label fields. Rendering can decide markdown vs HTML later.
Chosen Story tone lives in the core (result_story: drew / edged / beat / thrashed by margin). It's data-derived and deterministic, so it belongs with the logic and is unit-testable.
Chosen today includes fixtures of any status (scheduled, live, finished). The digest shows the whole day; filtering is a presentation concern.
Deferred Markdown/HTML rendering and the terrace digest CLI — next roadmap item.
Deferred The "data unavailable" wording for empty days — that's copy, it ships with the renderer. The core just returns empty lists today.
Deferred News headlines and competition filtering — input is already single-competition from the client, so the core doesn't re-filter.

Scores use a true en dash (–), not a hyphen. The winner/loser orientation comes from result.winner (HOME/AWAY/DRAW), so the bigger score is always quoted first.

How to see it work

Run the suite (18 tests, all green):

uv run pytest tests/test_digest.py -v

Lint clean:

uv run ruff check .

Try it in a REPL:

uv run python 
from datetime import datetime, UTC
from terrace.core.digest import build_digest
from terrace.core.models import Fixture, Competition, Team, MatchStatus

wc = Competition(code="WC", name="FIFA World Cup")
usa_wal = Fixture(id="1003", competition=wc,
    kickoff=datetime(2026,6,13,15,0, tzinfo=UTC),
    home=Team(name="USA"), away=Team(name="Wales"), status=MatchStatus.SCHEDULED)

d = build_digest([usa_wal], [], now=datetime(2026,6,13,6,0, tzinfo=UTC))
print(d.today[0].kickoff_label)        # 8:30 PM IST
print(d.match_of_the_day.reason)     # Prime-time pick: USA vs Wales at 8:30 PM IST.
