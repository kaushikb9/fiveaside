Concepts that may be new

1 · A pure, deterministic “editor” instead of an LLM

The section reads like an opinion (“this is the one to watch”), but there is no model call. The opinion is a scoring function over data already in hand. Same inputs → byte-identical output, every time.

# score = stakes + momentum
def _score(card):
    base     = card.fixture.matchday or 0   # deeper in the competition = higher stakes
    momentum = sum(1 for name in (home, away)
                   if name in winner_names)       # +1 per team already winning
    return base + momentum

Why it’s the right call here: the digest must be reproducible (tests assert exact markdown) and cheap. A handful of fields beat a non-deterministic, billable LLM call.

2 · Sorting is the tie-break — a stable key tuple

“Pick the max score, break ties by earliest kickoff, then id.” That entire sentence is one sort key. Python compares tuples left-to-right, so ordering the fields encodes the priority.

best = min(cards, key=lambda c: (-_score(c), c.kickoff_ist, c.fixture.id))
#                            ▲ negate    ▲ earlier      ▲ deterministic
#                            highest     wins ties      final tiebreak

The trick worth noticing: it uses min(...) with a negated score. Highest score becomes the smallest first element, while kickoff_ist and id stay ascending — so “biggest, then earliest” falls out of a single pass. It mirrors the existing pick_match_of_the_day style, so the codebase stays consistent.

Why it matters: without that last fixture.id term, two equally good fixtures at the same time could swap places between runs — and a test would flake. Determinism is a feature.

3 · Frozen pydantic models + an optional field that stays backwards-compatible

WhatToWatch(BaseModel, frozen=True) is immutable — once built it can’t be mutated, which makes it safe to pass around and trust. The new field on the digest is declared with a default:

what_to_watch: WhatToWatch | None = None

That = None is doing quiet but important work: every existing DailyDigest(...) call in the test suite stays valid without edits. The field is purely additive.

Why it’s the right call: additive, defaulted fields let a model grow without a migration or a sweep through every caller — the cheapest possible way to extend a shared type.

4 · “First applicable wins” — priority as a fall-through ladder

fun_fact() is a fixed ladder of facts. The first one that applies is returned; the rest never run. No config, no ranking — just ordered if blocks.

if results:                         # 1. biggest non-draw margin so far
    ...
    return f"Biggest win so far: {winner} {hi}–{lo} over {loser}."
if cards:                           # 2. fall back to a match count
    noun = "match" if n == 1 else "matches"
    return f"{n} {noun} on the card today."
return None                         # 3. nothing to say

Note the small craft: is_draw games are skipped (a 1–1 has no winner), and singular/plural is handled so it never prints “1 matches”.

Why it’s the right call: facts have a natural pecking order. A ladder makes that order explicit and trivially testable — one test even asserts the biggest-win branch beats the count branch.

5 · The “take” is a branch over which signal dominated

The one-liner isn’t a template with blanks — its shape changes based on why the fixture won, so the prose always matches the data.

conditionthe take it writes
both teams are recent winners“Both {home} and {away} arrive on the back of wins — this is the one to watch at {time}.”
else, a matchday exists“Matchday {n} and everything still to play for — {home} vs {away} at {time} is the pick.”
else (fallback)“{home} vs {away} at {time} is the pick of today’s slate.”

Every branch threads in kickoff_label, so the reader always gets the “when.”

Decisions & trade-offs

DecisionRationale
Compute only from fixtures + results already passed to build_digest Keeps core pure — no coupling to standings or sources/. Imports stay pydantic + stdlib + terrace.core.models, so the “no forbidden imports” test holds.
Two independent heuristics (match_of_the_day vs what_to_watch) Different questions: prime-time slot vs narrative stakes. Left the old one untouched to avoid touching its tests.
Markdown / CLI surface only Shippable thin slice. Showing the section on the web PWA (web/templates/digest.html, standings.html) was deferred — out of scope for this PR.
Render guards on None If there are no cards, the field is None and the section simply doesn’t render — graceful, no empty heading.
Subtlety to note: fun_fact reads all results “Biggest win so far” spans the season’s results, not just yesterday — intentional, and worth knowing when reading output.
